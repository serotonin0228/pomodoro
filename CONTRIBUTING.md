# Contributing to Pomodoro

Thanks for your interest in contributing.

## Before you start

- Search existing issues and pull requests to avoid duplicating work.
- For substantial changes, open an issue describing the proposed behavior and scope.
- Keep pull requests focused and include a brief description of what changed and why.

## Development setup

Use Node.js 22.13 or newer.

```bash
npm ci
npm start
```

Native development requires the Android SDK or, for iOS, macOS with Xcode. The `ios/` and `android/` directories are generated by Expo; changes to native configuration should normally be made in `app.json` or the `plugins/` config plugins.

## Quality checks

Run the checks relevant to your change before submitting a pull request:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

For browser-facing changes, run Playwright tests with the exported web app served on port 8081:

```bash
python3 -m http.server 8081 --directory dist
npm run test:e2e
```

The Playwright configuration uses `/usr/bin/chromium` unless `PLAYWRIGHT_CHROMIUM_EXECUTABLE` is set.

## Pull requests

- Describe the user-visible behavior and link any related issues.
- Include screenshots or a short recording for visual changes when practical.
- Note the platforms tested, especially for notifications, background behavior, and audio.
- Add or update tests when changing timer calculations, records, synchronization, or localization.
- Avoid committing generated native folders, build artifacts, secrets, and local `.env` files.

## Security and licensing

Do not share credentials, signing material, or personal data in issues or pull requests. Use a public Supabase publishable key only for local development and keep privileged keys private.

By contributing, you agree that your contribution may be distributed under the project's [MIT License](LICENSE). Any new third-party assets must have compatible usage rights and include appropriate attribution.
