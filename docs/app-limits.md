# Android 应用限制

主界面的「应用限制」进入本机设置；计时设置也提供入口。默认关闭，默认黑名单为空。

- 黑名单：拦截选中的应用；白名单：仅允许选中的应用。
- 仅本机控制、正在运行的专注计时中生效。暂停、休息和结束解除，倒计时在原生层按单调时钟自动到期；系统重启后旧会话失效。
- 桌面、番茄钟、系统设置、电话与紧急呼叫、权限控制器、输入法等必要入口不参与拦截。设备上部分不可见或没有启动入口的系统组件也放行。
- 开启总开关后，需要用户在 Android 系统的辅助功能设置中启用「番茄钟 · 应用限制」。用户可随时关闭权限或总开关。

## 实现

`FocusGuardService` 接收窗口切换和控件聚焦事件的应用包名，按 `FocusGuardPolicy` 判断。命中后先用辅助功能 HOME 动作退出受限应用，再启动现有 `MainActivity`，避免后台启动被静默拒绝时继续留在娱乐应用。用户可选开启“应用使用情况”特殊权限，原生服务每 400ms 查询最近的应用恢复事件，补充部分平板漏发窗口事件的问题；较旧的使用事件不能覆盖较新的窗口观察。不请求读取窗口内容、截图或手势权限，不上传应用列表或规则。应用列表通过 `MAIN/LAUNCHER` 的包可见性查询获取，不申请 `QUERY_ALL_PACKAGES`。策略与当前会话保存在本机 SharedPreferences，与 Supabase 无关。

前台通知的暂停/继续操作直接更新原生策略，不等待 JavaScript。倒计时的本机到期使用 `elapsedRealtime`，界面传入相对剩余时间，以免服务器时钟校正影响到期。

这是自愿的专注辅助，不能在普通 Android 安装环境中提供无法绕过的设备管理：受限应用可能短暂出现，关闭辅助功能、强行停止应用、厂商后台限制或未产生窗口切换事件时可能无法拉回。分屏、画中画、厂商桌面及系统版本差异需要真机验证。

## 验证

`python3 scripts/test-guard-policy.py` 使用 Gradle 缓存中的 Kotlin 编译器，在 JVM 上执行生产使用的策略，覆盖两种模式、必要应用、暂停/结束/休息、倒计时边界、正计时以及设备重启。原生发布构建验证模块、资源和服务声明；Web 回归只验证原有计时/音乐，不代表已在 Android 设备验证拦截。


v1.2.1：限制状态单独显示原生计时是否激活；“检查限制状态”可查看并自愿通过系统分享面板分享本机诊断。诊断只在内存中记录最近包名、事件数量和跳转结果，不自动上传，也不保存历史。读取不到 BOOT_COUNT 时改用启动时刻和 uptime 校验，不再一律停用限制。
